# XGO Dog 通信 API

[中文 README](../README_CN.md) · [English API](api_en.md)

本固件提供寄存器协议（旧）和主子地址协议（新）。两套协议可以在同一连接上使用，控制同一组机器人状态。

本文寄存器地址用十六进制表示，主地址、子地址和设备 ID 默认用十进制表示。`u8` 为无符号 8 位整数，`f32` 为 IEEE 754 单精度浮点数，`i32` 为有符号 32 位整数。

## 1. 连接

### 1.1 UART

| 参数 | 值 |
| --- | --- |
| 默认串口格式 | 115200 baud，8 数据位，无校验，1 停止位 |
| 主机串口 | UART0；UART1 的 ESP32 RX/TX 分别为 GPIO4/GPIO5 |
| 波特率索引 | `0`=115200，`1`=500000，`2`=921600，`3`=1000000，`4`=1500000，`5`=2000000 |

修改波特率仅影响收到该命令的 UART，主机随后切换到同一波特率。重启恢复默认值。FDI 串口 IMU 占用 UART0 时，主机改用 UART1 或 BLE。

### 1.2 BLE

| 项目 | UUID / 行为 |
| --- | --- |
| Service | `0000fff0-0000-1000-8000-00805f9b34fb` |
| 主机写入 | `0000fff2-0000-1000-8000-00805f9b34fb`，Write |
| 主机接收 | `0000fff1-0000-1000-8000-00805f9b34fb`，Notify |
| 广播名称前缀 | `XGO-M-`、`XGO-MW-` 或 `XGO-L-`，后接保存的名称后缀 |

连接后订阅 Notify，再发送协议帧。BLE 按协商后的 `MTU - 3` 字节分片发送；主机必须按字节流重组，不能把一条通知当成一帧。普通查询的回复从请求所在连接返回。

## 2. 帧格式和数据约定

### 2.1 请求与查询回复

```text
55 00 LEN CMD ADDR DATA... CHECKSUM 00 AA
```

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| 帧头 | 2 | `55 00` |
| `LEN` | 1 | 整帧字节数，`8 + DATA字节数`，范围 8～255 |
| `CMD` | 1 | 命令类型，见下表 |
| `ADDR` | 1 | 寄存器地址或主地址 |
| `DATA` | 0～247 | 命令数据 |
| `CHECKSUM` | 1 | `~(LEN + CMD + ADDR + sum(DATA)) & 0xFF` |
| 帧尾 | 2 | `00 AA` |

这是 8 位累加取反校验，不是 CRC。校验和与帧尾不正确的帧不执行。

| `CMD` | 含义 | 回复 |
| --- | --- | --- |
| `0x00` / `0x01` | 寄存器写入（旧） | 无 ACK |
| `0x02` | 寄存器读取（旧） | `0x12`，`ADDR` 与请求相同 |
| `0x03` | 主子地址写入（新） | 无 ACK |
| `0x04` | 主子地址读取（新） | `0x14`，`ADDR` 与请求相同 |

多字节数值默认小端。旧协议的航向角 `0x3F`、整数姿态 `0x66～0x68`、扩展舵机位置 `0xA1～0xA9` 使用大端，以下单独标明。

写入成功没有应答，也没有独立错误码；可读字段应通过查询确认。查询通常读取最新接收的设备状态或当前控制量，不会同步触发一次电机采样，也不提供单电机反馈时间戳。

速度指令持续生效，通信失联不自动清零。持续欠压或关机流程会停止接受写命令，读取仍可处理。

### 2.2 坐标与数值单位

| 字段 | 单位 / 语义 |
| --- | --- |
| 机身、足端、机械臂位置 | mm；机身 Z 是绝对高度，不是相对站立高度的偏移 |
| 机身 RPY、舵机角度、航向角 | °；IMU yaw 为连续累计角，不限于 ±180° |
| IMU 加速度 | m/s²，包含重力，采用对应驱动的输出轴系 |
| IMU 陀螺仪 | °/s，I²C IMU 为扣除上电零偏后的输出；ICM42670 对外输出另有小于 2°/s 的死区 |
| 四轮实际线速度反馈 | m/s，按轮半径 22mm 从电机转速换算 |
| 四轮里程反馈 | 有符号累计计数，固件按电机位置值除以 16 并换算安装方向；不是 mm |
| `vx` / `vy` 运动指令 | 内部步幅控制量，步态使用 mm 尺度，不是底盘实际 m/s |
| `yaw_speed` 运动指令 | 内部转向量；腿部航向目标按每个标称 5ms 控制步累加该值，纯轮模式直接用于转向映射 |

输入浮点数应为有限数值。目标位姿、关节位置和电机输出最终受机型范围、运动学可达性及输出限幅约束；写入控制量不等于保证实际到达。

电量读数为 0～100% 的估计值。按运动指令、动作状态和目标变化判断忙闲，舵机/轮子的速度反馈不参与判断。运动、动作执行及 Reset 的 600ms 恢复期内保持上次百分比；指令停止满 1s，且最近 300ms 电压采样的最大差值 ≤0.10V 后，按机型曲线继续平滑更新。持续采样和欠压保护独立运行：Mini / Mini 轮足的总压阈值为 6.84V，Lite 为 6.70V；总压均值持续低于或等于阈值约 4s 后，执行原有复位、趴下、卸载及关机流程。短时压降不会直接改写显示百分比。


### 2.3 机型范围

旧协议的缩放区间和新协议的有效位姿区间如下。轮足 Mini 的参数由固件检测到轮子后选用。

| 参数 | Mini | Mini 轮足 | Lite |
| --- | ---: | ---: | ---: |
| 机身 X / mm | −30～30 | −30～30 | −20～20 |
| 机身 Y / mm | −18～18 | −16.2～16.2 | −16～16 |
| 机身 Z / mm | 70～120 | 70～114 | 65～110 |
| 默认站立高度 / mm | 100 | 100 | 85 |
| Roll / Pitch / Yaw / ° | −18～18 | −18～18 | −15～15 |
| `vx` 指令区间 | −33～33 | −26.4～26.4 | −14.3～22 |
| `vy` 指令区间 | −15～15 | −18～18 | −12.5～12.5 |
| `yaw_speed` 指令区间 | −0.75～0.75 | −0.75～0.75 | −0.75～0.75 |

旧协议一般缩放规则为：

```text
写入：value = byte / 255 × (maximum − minimum) + minimum
读取：byte = trunc((value − minimum) / (maximum − minimum) × 255)，超界饱和到 0 或 255
```

只有以下明确支持的连续块才会将多个字节写入多个地址；普通单字节寄存器只使用第一个数据字节。

## 3. 寄存器协议（旧）

### 3.1 写入接口

发送 `CMD=0x01` 或 `0x00`，`ADDR` 为下表地址，`DATA` 按表编码。

| 地址 | `DATA` | 功能 |
| --- | --- | --- |
| `0x02` | `baud_index:u8` | 当前 UART 波特率索引 0～5 |
| `0x03` | `enabled:u8` | 动作循环：0 关闭并复位，非 0 开启内建动作循环 |
| `0x04` | `enabled:u8` | 舵机零点标定：非 0 进入，0 在已进入标定时保存并重启；不是 IMU 标定 |
| `0x06` | `01` | 将当前 IMU yaw 设为航向原点 |
| `0x08` | `enabled:u8` | 1 开启主动反馈，其他值关闭；反馈目的端口切到本命令所在端口 |
| `0x09` | `gait:u8` | 步态类型，见枚举表 |
| `0x13` | `name_bytes[1..30]` | 保存 BLE 名称后缀，不含长度前缀；重启后与机型前缀组合生效 |
| `0x20` | 见使能格式 | 舵机使能，进入关节直接控制模式 |
| `0x30` | `vx:u8` | 缩放后的 X 运动指令 |
| `0x31` | `vy:u8` | 缩放后的 Y 运动指令 |
| `0x32` | `yaw_speed:u8` | 缩放后的转向指令 |
| `0x33` / `0x34` / `0x35` | `value:u8` | 缩放后的机身 X / Y / Z |
| `0x36` / `0x37` / `0x38` | `value:u8` | 缩放后的机身 Roll / Pitch / Yaw |
| `0x39` / `0x3A` / `0x3B` | `period:u8` | Roll / Pitch / Yaw 周期运动参数 |
| `0x3D` | `preset:u8` | 步频档位：0 正常，1 低速，2 高速 |
| `0x3E` | `action:u8` | 动作编号；255 复位并停止动作循环 |
| `0x3F` | `offset:i16 大端` | 目标航向为 `航向原点 + offset`，并开启航向跟踪 |
| `0x40～0x4B` | `position:u8` 或连续字节块 | 四条腿的足端 X/Y/Z，按机型范围缩放；进入足端直接控制模式 |
| `0x50～0x5B` | `angle:u8` 或连续字节块 | 12 个腿部舵机角度，按对应舵机关节范围缩放；进入关节直接控制模式 |
| `0x5C` | `speed:u8` | 腿部舵机速度参数 0～255；0 为不限速 |
| `0x5D` / `0x5E` | `angle:u8` | 舵机 ID52 / ID53 角度，按对应关节范围缩放；切到机械臂关节控制 |
| `0x5F` | `01` | 执行舵机归中流程 |
| `0x61` | `mode:u8` | IMU 稳定模式：0 关闭并清零机身 RPY，1 开启，2 保留手动姿态分支 |
| `0x69～0x6C` | `R:u8 G:u8 B:u8` | 写一个逻辑 RGB 通道，按地址依次为 1～4 |
| `0x69～0x6C` | `R1 G1 B1 ... R4 G4 B4` | 数据至少 12 字节时，写全部 4 个逻辑 RGB 通道 |
| `0x70` | `angle:u8` | 舵机 ID54 转台角度，按对应关节范围缩放 |
| `0x71` | `angle:u8` | 舵机 ID51 夹爪角度，按对应关节范围缩放 |
| `0x72` | `mode:u8` | 机械臂坐标模式：0 随机身，1 启用机身位置/俯仰补偿 |
| `0x73` / `0x74` | `position:u8` | 机械臂 X / Z，分别映射 −80～160mm / −100～160mm；切到坐标控制 |
| `0x75` | `speed:u8` | 机械臂舵机速度参数 0～255；0 为不限速 |
| `0x76` | `theta:u8` | 极坐标角度，映射 70～270°；与当前半径一起生成机械臂 X/Z |
| `0x77` | `radius:u8` | 极坐标半径，映射 80～140mm；与当前角度一起生成机械臂 X/Z |
| `0x80` / `0x81` / `0x82` | `period:u8` | 机身 X / Y / Z 周期运动参数 |
| `0x90` / `0x91` | `state:u8` | 扩展输出 GPIO26 / GPIO27；0 低电平，1 高电平 |
| `0xA1～0xA9` | `position:u16 大端` | 扩展舵机 ID91～99 的原始位置值，每次写一个舵机 |
| `0xB0` | `mode:u8` | 运动模式：0 混合、1 轮驱配合腿部转向、2 腿式/独立轮、3 纯轮；切换时清零 `vx`、`vy`、内部 `vyaw` 及四轮指令，`yaw_speed` 保留 |
| `0xB1` | `w10:u8 w20:u8 w30:u8 w40:u8` | 四轮独立驱动档位，至少 4 字节；切换到模式 2 |
| `0xF0` | `mode:u8` | 工厂循环：0 关闭，1 位姿周期循环，2 移动和位姿循环 |

写 `0x30～0x32` 会切到整机控制并关闭 IMU 自稳定。小指令存在运动死区。只改其中一轴会保留其他轴当前值，停止时应明确清零全部运动轴和独立轮输入。

逻辑 RGB 通道数为 4；当前板级输出驱动刷新前 3 个物理像素。

#### 舵机使能格式：`0x20`

| 格式 | 数据 | 含义 |
| --- | --- | --- |
| 全部舵机 | `00` / `01` | `00` 使能，`01` 卸力 |
| 舵机组 | `11～15` / `21～25` | 低 4 位为组号；`1x` 卸力，`2x` 使能 |
| 指定 ID | `[id, disabled]...` | 可连续多个二字节项；`disabled=0` 使能，非 0 卸力 |

组 1～4 分别为 ID11～13、21～23、31～33、41～43，组 5 为 ID51～54。此处指定 ID 的第二字节是 `disabled`，与新协议的 `enabled` 相反。

#### 连续足端与腿关节

| 腿组 | 足端 X/Y/Z 地址 | 舵机地址 | 舵机 ID |
| --- | --- | --- | --- |
| 1 | `40 41 42` | `50 51 52` | 11、12、13 |
| 2 | `43 44 45` | `53 54 55` | 21、22、23 |
| 3 | `46 47 48` | `56 57 58` | 31、32、33 |
| 4 | `49 4A 4B` | `59 5A 5B` | 41、42、43 |

表中地址均为十六进制。从任意起始地址连续写入，最多写到该块末地址。不会跨入下一功能块。足端 Y 输入为横向调节量，内部会减去对应腿的安装偏移。

#### 四轮档位：`0xB1`

`0x00` 为负向最大档，`0x80` 为停止，`0xFF` 为正向最大档。四字节分别控制 ID10、20、30、40。安装方向由固件处理。

```text
d = byte − 128
drive = trunc(230 × d / (d > 0 ? 127 : 128))
```

驱动指令范围为 −230～230。档位不表示实际线速度；读取 `0xB1` 返回实际 m/s 反馈。

### 3.2 读取接口

发送 `CMD=0x02`，`DATA=[N]`，其中 `N` 为期望读取的字节数。回复 `CMD=0x12`，`DATA` 为读取结果。

| 地址 | 请求 `N` | 回复数据 |
| --- | ---: | --- |
| `0x00` | 1 | `00` |
| `0x01` | 1 | 电量百分比 `u8` |
| `0x02` | 1 | 固定返回 `01`；不能用它区分当前实际机型 |
| `0x07` | 10 | 固件版本，固定 10 字节 ASCII，可能以 `00` 结尾 |
| `0x30～0x38` | 1 | 对应当前机身控制量，按同一缩放范围编码成 `u8` |
| `0x3F` | 1 | 航向跟踪状态 `u8`，不是目标航向角 |
| `0x50` | 1 | ID11 实际角度，缩放为 `u8` |
| `0x50` | 16 | 全部 16 个舵机实际角度，按下方 ID 顺序返回 16 个 `u8` |
| `0x51～0x5B` | 1 | 对应腿部舵机实际角度，缩放为 `u8` |
| `0x5D` / `0x5E` / `0x70` / `0x71` | 1 | ID52 / ID53 / ID54 / ID51 实际角度，缩放为 `u8` |
| `0x61` | 1 | 当前 IMU 稳定模式 `u8` |
| `0x62` / `0x63` / `0x64` | 4 | IMU Roll / Pitch / Yaw，`f32` 小端 |
| `0x66` / `0x67` / `0x68` | 2 | IMU Roll / Pitch / Yaw，向零截断后的 `i16` 大端 |
| `0x92` | 1 | GPIO36 模拟输入量化值 `u8`，0～255 |
| `0x93` | 1 | GPIO39 数字输入 `u8`，0 或 1 |
| `0xB1` | 16 | ID10、20、30、40 的实际线速度，4 个 `f32` 小端 |
| `0xB2` | 16 | ID10、20、30、40 的累计里程计数，4 个 `i32` 小端 |

`0x50` 的请求长度只要不为 1，固件都回复全部 16 个舵机；客户端应使用表中的 16。固定长度字段以实际回复长度为准。

只有表内地址有定义。其他地址没有统一的“不支持”回复，可能返回该端口保留的旧数据；不能用试读未知地址检测能力。单字节字段请按 1 字节读取，额外字节不表示连续寄存器。

### 3.3 关机反馈

长按电源键或持续欠压触发关机时，固件下发趴下动作。首帧在约 300 ms 后发送，随后每隔约 300 ms 通过 UART0 和 UART1 各发送一帧，直到切断电源。此反馈由固件主动发送，无需查询或开启状态推送。

| `CMD` | `ADDR` | `DATA` | 完整报文 |
| --- | --- | --- | --- |
| `0x12` | `0x00` | `FF` | `55 00 09 12 00 FF E5 00 AA` |

使用 FDI 串口 IMU 的机型应从 UART1 接收，UART0 仍使用 FDI 的引脚和波特率。

## 4. 主子地址协议（新）

### 4.1 子字段编码

写入使用 `CMD=0x03`，`ADDR=main`。根据接口选择以下编码，一帧只对应一个主地址：

| 字段类型 | `DATA` 格式 |
| --- | --- |
| 浮点字段 | `[sub:u8, value:f32小端]...`，每项 5 字节 |
| 字节字段 | `[sub:u8, value:u8]...`，每项 2 字节 |
| 自定义字段 | 见对应接口，如 ID 使能、BLE 名称和 RGB |

浮点字段可以只更新需要的子地址；未提供的字段保留原值。同一帧内重复同一子地址时，后面的写入覆盖前面的写入。

读取使用 `CMD=0x04`，`ADDR=main`，`DATA=[sub1,sub2,...]`，只发送子地址，不发送值。回复 `CMD=0x14`，按请求顺序返回支持的子字段。浮点项为 `sub + f32`，字节项为 `sub + u8`。固件版本使用专用长度格式。

未实现的主地址、空子地址列表或全部未知的子地址不回复；未知子地址不出现在结果中。回复数据最多 240 字节，不能假定请求了多少项就会返回多少项。

### 4.2 状态与连接

| 主地址 | 权限 | 子地址 / 数据格式 | 功能 |
| --- | --- | --- | --- |
| 1 | R | 读 `[1]`；回复 `[1,10,version[10]]` | 固件版本，固定 10 字节 ASCII |
| 2 | R | 读 `[1]`；回复 `[1,battery:u8]` | 电量百分比 |
| 3 | W | `[1,enabled:u8]`，整份数据恰好 2 字节 | 1 开启主动反馈，其他值关闭；反馈端口切到当前端口 |
| 4 | W | `[1,enabled:u8]`，恰好 2 字节 | 舵机零点标定，含义同旧 `0x04` |
| 5 | W | `[1,baud_index:u8]`，恰好 2 字节 | 当前 UART 波特率索引 0～5 |
| 6 | W | `[1,length:u8,name[length]]` | 保存 BLE 名称后缀，length 为 1～30，数据长度须恰好匹配 |
| 7 | W | `[1,mode:u8]`，恰好 2 字节 | 工厂循环：0 关闭，1 位姿循环，2 移动和位姿循环 |

主地址 1、2 的写入不改变状态。主地址 3～7 没有对应查询接口。

### 4.3 整机控制

| 主地址 | 权限 | 子地址 | 类型 | 功能 |
| --- | --- | --- | --- | --- |
| 10 | R/W | 1、2、3、4、5、6 | `f32` | 机身 X、Y、Z、Roll、Pitch、Yaw |
| 11 | R/W | 1、2、3、4、5、6 | `f32` | 机身 X、Y、Z、Roll、Pitch、Yaw 的周期参数，范围 0～255 |
| 20 | R/W | 1、2、3 | `f32` | `vx`、`vy`、`yaw_speed` 运动指令；读取的是当前控制量 |
| 21 | W | 1 | `u8` | 动作编号；255 复位并停止动作循环 |
| 21 | W | 2 | `u8` | 动作循环：0 关闭并复位，非 0 开启 |
| 22 | W | 1 | `f32` | 目标航向偏移角；目标为 `航向原点 + 偏移角`，开启跟踪，关闭 IMU 自稳定 |
| 23 | W | 1 | `u8` | 步频档位：0 正常、1 低速、2 高速 |
| 23 | W | 2 | `u8` | 步态类型，见枚举表 |
| 24 | W | 1 | `u8` | 写 1，将当前 IMU yaw 设为航向原点；数据恰好 `[1,1]` |

主地址 10、11、20、22 会切到整机控制。主地址 20 同时关闭 IMU 自稳定，并对全部运动轴应用小指令死区。主地址 21、23 的一帧可以包含多个字节子项；主地址 22～24 没有查询接口。

运动指令全部回到死区时，固件取消相对航向保持。当前摆腿完成落脚，下一段运动使用当时的有效 IMU 航向作为参考。单独松开转向且继续平移时，固件保留已累计的目标航向。显式目标航向命令按各模式原有规则处理。

机身位姿周期参数并非秒数：

```text
period = 0：结束当前周期后停止
period > 0：周期毫秒 = 1000 + period / 255 × 3000
```

周期 X/Y 和 RPY 的幅值由机型最大值的 80% 决定；Z 以高度区间中点为中心，幅值为半区间的 80%。写入 0 不是立即取消当前周期；动作复位 255 会清除周期状态并恢复站立位姿。

### 4.4 足端、舵机与机械臂

| 主地址 | 权限 | 子地址 / 格式 | 功能 |
| --- | --- | --- | --- |
| 30 | R/W | `1..12:f32`，每腿按 X/Y/Z 连续排列 | 四腿足端基准位置；写入切到足端直接控制 |
| 40 | R/W | 子地址为设备 ID，值为角度 `f32` | 写目标角度、读反馈角度；写入切到关节直接控制 |

| 41 | W | `[2,group_code:u8]...` | 组使能代码同旧 `0x20` 的单字节组格式 |
| 43 | W | `[1,speed:u8]`，恰好 2 字节 | 腿部舵机速度 0～255；0 为不限速 |
| 44 | W | `[1,1]` | 舵机归中流程 |
| 51 | R/W | 子地址 1；写 `u8`，读 `f32` | 写夹爪比例 0～100，线性对应关节最小～最大角度，超过 100 按 100；读 ID51 实际角度，单位 ° |

| 53 | R/W | 见下表，均为 `f32` | 机械臂坐标控制与转台 |

主地址 30 的 Y 写入量会减去该腿的安装偏移，读取返回内部足端基准 Y，所以 Y 的读写值不完全对称：

```text
内部Y = 写入Y − sign × Ld
腿组1..4 的 sign = −1、+1、+1、−1
Mini 的 Ld = 31.6mm；Lite 的 Ld = 28.1mm
```

主地址 40 支持内置舵机 ID 和扩展舵机 ID91～100。扩展舵机需要实际连接，查询返回固件保存的反馈值；本固件正常电机轮询不包含这些扩展设备。混合列表中的 255 不会展开，只有单独请求 `[255]` 才表示全部内置舵机。

主地址 41 的指定 ID 使能使用 `enabled`，与旧 `0x20` 的指定 ID `disabled` 相反。自定义 ID 项和组项可连续排列。写主地址 40 中的 ID52、53 会关闭机械臂坐标控制。

#### 机械臂坐标：主地址 53

| 子地址 | 写入 | 读取 | 单位 / 范围 |
| --- | --- | --- | --- |
| 1 | X 目标 | 当前 X 控制量 | mm，建议 −80～160 |
| 2 | Z 目标 | 当前 Z 控制量 | mm，建议 −100～160 |
| 3 | 极坐标半径 r | 当前 r 控制量 | mm；需满足机械臂可达性 |
| 4 | 极坐标角度 θ | 当前 θ 控制量 | **rad**，不是 ° |
| 5 | ID54 目标角度 | ID54 实际角度 | ° |

写入任一子项会切到机械臂坐标控制。只要同帧包含子地址 3 或 4，固件就以极坐标重新计算 X/Z，覆盖该帧的 X/Z 写入：`X = −r cos(θ)`、`Z = r sin(θ)`，结果按 X/Z 范围限幅。只写 X 或 Z 时，另一个坐标保留原值。

### 4.5 IMU、外设与轮子

| 主地址 | 权限 | 子地址 / 格式 | 功能 |
| --- | --- | --- | --- |
| 60 | R | `1..9:f32` | 1～3 为 Roll/Pitch/Yaw；4～6 为 AccX/AccY/AccZ；7～9 为 GyroX/GyroY/GyroZ |
| 61 | W | `[1,mode:u8]`，恰好 2 字节 | IMU 稳定模式 0/1/2，含义同旧 `0x61` |
| 62 | W | `[channel:u8,R:u8,G:u8,B:u8]...` | RGB，channel 为 1～4，可连续多个四字节项 |
| 63 | R/W | 1、2，`u8` | 写 GPIO26 / GPIO27 输出；读 GPIO36 模拟输入 / GPIO39 数字输入；读写对象不同 |
| 70 | W | `[1,mode:u8]`，恰好 2 字节 | 接受模式 0 混合、1 轮驱配合腿部转向、2 腿式/独立轮；清零 `vx`、`vy`、内部 `vyaw` 和四轮指令，`yaw_speed` 保留 |
| 71 | R/W | `1..4:f32` | 写 ID10、20、30、40 的独立驱动输入；读对应实际线速度 m/s |
| 128 | R/W | `1..10:f32` | 10 个用户调试数值，无默认控制副作用 |

主地址 63 的写入字节建议只使用 0/1。读取子地址 1 为量化模拟输入 0～255，子地址 2 为数字输入 0/1；并不回读输出状态。

FDI 串口 IMU 适配器只更新 Roll/Pitch/Yaw，不采集上述加速度和陀螺仪字段；不能将这些字段的初始零值视为有效采样。

主地址 71 的写入是保留的独立轮输入比例：安装方向修正后乘 100，最终输出限制为 −230～230；绝对值小于 0.05 的输入置 0。输入 ±2.3 对应输出 ±230，超过该范围仍受输出限幅。**写入值不能作为实际 m/s 保证值**。写入后切到模式 2，未更新的轮子保留其原指令。

独立轮指令由整机控制周期计算。如果此前进入了足端或关节直接控制，先通过主地址 20 下发全零运动量切回整机控制，再写主地址 71 或旧 `0xB1`。

轮式模式 3 通过旧寄存器 `0xB0` 设置，新主地址 70 不接受 3。前后移动由轮子完成；`|vy| > 1` 时由腿执行侧移，不将前后轮驱指令叠加为腿的前后步幅。腿部动作使用当前选择的步态，指令清零后按原步态收脚。

模式 3 的运动条件为 `|vx| > 5`、`|vy| > 1` 或 `|yaw_speed| > 0.1`。IMU 就绪且反馈有效时，在本次运动开始记录当前 yaw，随后按实际控制间隔累计目标航向：`目标 yaw += yaw_speed × dt / 0.005s`。手动原地转向也参与累计。

- 航向误差为 `目标 yaw − 当前 IMU yaw`；绝对值 ≤1° 为死区，不纠偏。
- 1° < 误差绝对值 ≤10°：轮子转向量为 `0.05 × 误差`，不触发转向迈腿。
- 误差绝对值 >10°：用 `0.33 × 误差` 作为腿部转向步幅输入，受机型原有转向限幅约束；轮子航向纠偏量为零。回到 10° 内恢复差速纠偏，腿部平稳收脚；仍有侧移指令时继续侧移步态。
- 四轮输出按以下公式混合，轮速保持开环，无积分控制器；前后驱动先为差速预留余量，避免转向被限幅抹掉：

  ```text
  turn = clamp(40 × 轮子转向量, −230, 230)
  driveLimit = 230 − |turn|
  drive = clamp(20 × vx, −driveLimit, driveLimit)
  order[i] = 安装方向符号[i] × drive − turn
  ```

- 运动指令全部回到死区时，立即取消航向参考并清零轮子输出，腿部按当前步态收脚；未追上的转向目标不继续执行。仍在平移而仅松开转向时，保留已累计的目标航向。
- IMU 未就绪、反馈超时或无效时，不累计目标航向、不进行轮子或腿部航向纠偏；有效反馈恢复后从当前航向重新开始。前后轮驱、腿部侧移仍按原运动指令执行。
- 不执行独立目标航向跟踪（旧 `0x3F` / 新主地址 22）；这些接口在其他运动模式中的语义保持不变。

## 6. 主动反馈

旧 `0x08` 或新主地址 3 开启后，固件向最后选择的反馈端口推送以下固定 **254 字节** 帧。主动反馈端口是全局选择，一次只选一个端口；再次设置会切换目的端口。

```text
55 00 PAYLOAD[250] 00 AA
```

主动反馈没有 `LEN`、`CMD`、`ADDR` 或累加校验字节。下表的整帧偏移和负载偏移均从 0 开始。多字节字段均为小端，保留字节为 0。

| 整帧偏移 | 负载偏移 | 长度 | 类型 | 字段 |
| ---: | ---: | ---: | --- | --- |
| 2 | 0 | 1 | `u8` | 电量百分比 |
| 3 | 1 | 3 | 保留 | 0 |
| 6 | 4 | 4 | `f32` | X 运动控制量乘以 1/74，属于指令值 |
| 10 | 8 | 4 | `f32` | `vy` 运动控制量 |
| 14 | 12 | 4 | `f32` | 机身里程 X 字段，当前实现初始化为 0，未累计更新 |
| 18 | 16 | 4 | `f32` | 机身里程 Y 字段，当前实现初始化为 0，未累计更新 |
| 22 | 20 | 12 | `f32[3]` | IMU Roll、Pitch、Yaw |
| 34 | 32 | 12 | `f32[3]` | IMU AccX、AccY、AccZ |
| 46 | 44 | 12 | `f32[3]` | IMU GyroX、GyroY、GyroZ |
| 58 | 56 | 64 | `f32[16]` | 16 个内置舵机实际角度，单位 °，按 ID 顺序 |
| 122 | 120 | 64 | `f32[16]` | 舵机速度换算值：内部 `fb_vel × 360 / 4096`，不作为各舵机型号统一的 °/s 定义 |
| 186 | 184 | 16 | `f32[4]` | ID10、20、30、40 实际线速度，m/s |
| 202 | 200 | 16 | `i32[4]` | ID10、20、30、40 累计里程计数 |
| 218 | 216 | 34 | 保留 | 0 |

推送调度目标间隔为 20ms。UART 忙时会推迟发送；115200 baud 发送完整 254 字节需要约 22ms，因此不能把收到的帧率作为电机采样周期。BLE 通知可能拆成多段，仍按完整 254 字节重组。

## 7. 组包示例

下列十六进制示例均为完整请求帧：

| 操作 | 请求 |
| --- | --- |
| 旧协议读取版本 | `55 00 09 02 07 0A E3 00 AA` |
| 将当前 UART 切换到 500000 baud | `55 00 09 01 02 01 F2 00 AA` |
| 旧协议开启主动反馈 | `55 00 09 01 08 01 EC 00 AA` |
| 旧协议关闭主动反馈 | `55 00 09 01 08 00 ED 00 AA` |
| 旧协议四轮停止 | `55 00 0C 01 B1 80 80 80 80 41 00 AA` |
| 新协议读取 IMU RPY（main=60） | `55 00 0B 04 3C 01 02 03 AE 00 AA` |
| 新协议读取全部内置舵机（main=40） | `55 00 09 04 28 FF CB 00 AA` |

Python 组包和解码示例：

```python
import struct

def frame(command: int, address: int, data: bytes = b"") -> bytes:
    if len(data) > 247:
        raise ValueError("payload exceeds 247 bytes")
    body = bytes([8 + len(data), command, address]) + data
    checksum = (~sum(body)) & 0xFF
    return b"\x55\x00" + body + bytes([checksum, 0x00, 0xAA])

def float_fields(values: dict[int, float]) -> bytes:
    return b"".join(bytes([sub]) + struct.pack("<f", value)
                    for sub, value in values.items())

# 查询：只发送子地址列表。
read_imu = frame(0x04, 60, bytes([1, 2, 3]))
read_motors = frame(0x04, 40, bytes([0xFF]))

# 写入：浮点字段使用 sub + little-endian float32。
set_pose = frame(0x03, 10, float_fields({1: 0.0, 2: 0.0, 3: 100.0}))
stop_body = frame(0x03, 20, float_fields({1: 0.0, 2: 0.0, 3: 0.0}))
stop_wheels = frame(0x01, 0xB1, bytes([0x80] * 4))

# 已完成整帧校验的 0x14 浮点回复，其 DATA 可按 5 字节项解码。
def decode_float_fields(data: bytes) -> dict[int, float]:
    if len(data) % 5:
        raise ValueError("invalid float field payload")
    return {data[i]: struct.unpack_from("<f", data, i + 1)[0]
            for i in range(0, len(data), 5)}
```

接收端应先完成分片重组、长度和校验检查，再按 `CMD + ADDR` 选择解码方式；版本回复、字节字段回复和主动反馈不能套用浮点子字段解码器。
